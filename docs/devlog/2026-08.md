# Development log - 2026-08

## 2026-08-02 - google-cli gains a calendar surface and joins the standalone bundle

**Result**

- `calendar calendars list` and `calendar events list|get|create|update|delete` shipped
  under `google.calendar.*` command ids, with optional Google Meet conference creation on
  event mutation, and `google-cli` was added to the standalone CLI bundle. Releases 1.4.0
  and 1.5.0 carried the work.
- `NILS_GOOGLE_015` through `017` were reserved for calendar invalid input, not found, and
  runtime failure, with the registry and the crate contract updated together.

**Why / context**

- The point of the surface is to let a consumer turn a note into a real calendar event
  rather than a cron reminder. Event mutation beyond create/update/delete, calendar
  creation and deletion, and ACL changes were deliberately left out of scope.
- `--calendar-id` is required everywhere and no aliases are resolved, so the crate stays
  generic: a consumer that maps its own identifiers to calendars owns that mapping and its
  fail-closed behavior.
- Timed values are normalized to a complete RFC3339 `dateTime` before sending, because
  Calendar v3 answers HTTP 400 for a seconds-less `HH:MM`; a malformed clock is rejected
  locally instead of being forwarded. All-day `--end` stays exclusive to match the API, and
  `--from`/`--to` require an offset because the list API has no companion `timeZone` field.
- HTTP 410 Gone maps to the calendar not-found error alongside 404, since Calendar answers
  410 for an already-deleted event and a repeated delete should read as not-found rather
  than a raw HTTP failure.
- The `calendar` scope is requested in `auth add`; stored tokens are unaffected because a
  refresh token is bound to the scopes granted at authorization time.
- The crate's earlier exclusion from the standalone bundle cited Turso and simsimd
  dependencies its tree no longer has, and requiring an OAuth login before use is allowed by
  the bundle manifest's own inclusion rule.

**Evidence**

- PRs #218 (calendar surface and bundling) and #220 (events delete), plus commit `5dd5e54`
  for partial updates and Meet links. Fixture mode resolves the event id before reporting a
  successful delete, so the not-found path is exercised without network access and fixture
  mode still mutates nothing.

## 2026-08-02 - CI can be dispatched manually for an ungated main commit

**Result**

- The CI workflow accepts `workflow_dispatch`.

**Why / context**

- A push whose author GitHub declines to run Actions for lands on `main` with no `validate`
  check, and the release workflow's CI gate then blocks on a commit that is otherwise fine.
  Without a manual lever the only ways out are rewriting `main` or tagging an unverified
  commit, so the dispatch keeps recovery inside the existing gate rather than around it.

**Evidence**

- PR #221.
