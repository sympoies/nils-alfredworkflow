# Development log - 2026-07

## 2026-07-29 - Ordered Alfred feedback survives Alfred's own knowledge ranking

**Result**

- `alfred-core` gained top-level `skipknowledge` support, serialized only when configured,
  and it is enabled for the uid-based ordered rows in the bangumi, market, memo, and
  multi-timezone workflows. Workflow contracts and tests assert stable row order and reject
  item-level `skipknowledge`.

**Why / context**

- Alfred reorders results by its own learned usage ranking when items carry a `uid`. For a
  list whose order *is* the information (timezones in configured order, favorites in
  configured order, memos newest-first), that silently scrambles the answer while the rows
  themselves look correct.
- The flag is top-level only because Alfred defines it there; accepting it per item would
  let a workflow express something the format cannot honor, so tests reject it explicitly.

**Evidence**

- Commit `ed67e67`.

## 2026-07-26 - Project validation gates are consolidated behind one wrapper

**Result**

- The local wrapper owns locked Node setup and the ordinary CI phases, specialist references
  load on demand, and contract tests enforce the routing.

**Why / context**

- Node version selection had been duplicated between the local gate and CI, so the two
  could disagree about which interpreter ran the scraper tests. Making the wrapper own the
  setup is what keeps `local-pre-commit.sh --mode ci` an honest parity claim.

**Evidence**

- Commit `c192dda`; `scripts/tests/local_pre_commit_contract.test.sh` pins the phase
  routing.

**Links**

## 2026-07-10 - codex account switching routes through an authority host

**Result**

- Remote profile switching is delegated to an installed locked peer helper with access-only
  pull and fail-closed sync; the exact macOS arm64 `nils-cli` release is bundled with
  checksum verification; and replica-side auth writers (login, save, remove) are disabled
  whenever Alfred is operating against a remote authority.
- Both implicit-refresh flags are forced false for every remote-mode subprocess, release
  archive digests are pinned, and release metadata audits authenticate with a
  workflow-scoped read token while ignoring any ambient curl configuration.

**Why / context**

- Credentials have exactly one owner. Letting a replica write auth state produces two
  divergent sources of truth, and the divergence is only discovered when a token stops
  working, so the replica is made read-only by construction rather than by convention.
- Disabling the default curl configuration before adding the bearer header is a deliberate
  defense: a hostile `~/.curlrc` with verbose or trace defaults would otherwise write the
  workflow-scoped token into a log file.
- Pinning the release archive digest (rather than trusting the download URL) is what makes
  "bundled runtime" a verifiable claim; packaging policy was aligned to the
  download-and-verify path, and the older local-override and `cargo install` resolution
  orders were retired because no bundled workflow runtime used them.

**Evidence**

- PR #211, delivered across eight review rounds covering lock contention, helper failures,
  profile grammar (including leading-hyphen rejection), checksum pairs per pinned target,
  and pin preflight; PR #212 closed the residual review threads and added the smoke
  assertion that remote `auth use` delivers `CODEX_AUTO_REFRESH_ENABLED` and
  `CODEX_AUTH_REMOTE_REFRESH` as false to the peer helper.
- Cross-architecture package smoke stays checksum-verified without executing the macOS
  binary, so the Linux CI host can validate a macOS artifact.
