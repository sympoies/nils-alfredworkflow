# Development log - 2026-10

## 2026-10-18 - Preserve Calendar action identities in failure envelopes

### Result

- Calendar failures now identify supported actions, including create and update
  invalid-input errors; unresolved actions retain generic group IDs.

### Why / context

- Consumers correlate diagnostics to the invoked action. Resolve only supported
  action tokens so an unknown token cannot become a claimed command identity.

### Evidence

- Before production edits, both create/update invalid-flag regressions failed
  with generic IDs (exit 101). After the fix, cargo test -p nils-google-cli
  --test integration calendar_read:: passed all 14 tests, covering every
  supported action, group aliases, fallback IDs, schema and error codes.

## 2026-10-18 - Track the zbus 5 maintenance-advisory exceptions

### Result

- The dependency gate explicitly accepts only RUSTSEC-2026-0370, 0371 and 0372
  pending migration of the keyring/secret-service chain to zbus 6 or removal of
  the affected crates.

### Why / context

- All three RustSec records are informational unmaintained notices with no
  patched versions. A compatible transitive update is unavailable in the locked
  credential-storage chain, so retain the existing dependencies and every other
  policy check while tracking removal in issue #277.

### Evidence

- The unchanged baseline cargo deny --all-features --workspace check advisories
  bans licenses sources failed all three advisory IDs; the same command passed
  after the narrow exceptions. Both runs used the 6 GiB memory scope with no
  swap.
