# Development log - 2026-03

## 2026-03-28 - Markdown lint moves from markdownlint-cli2 to rumdl

### Result

- `markdownlint-cli2` was replaced by `rumdl`, with the config in `.rumdl.toml`, the audit
  script repointed, and `rumdl` tracked in the package lock and third-party artifacts.

### Why / context

- The Node lint step was one of the slower parts of the local gate on a repository whose
  Markdown surface keeps growing (every workflow README is a delivery artifact). `rumdl`
  runs the same rule set natively.
- `.rumdl.toml` keeps MD013 at 140 columns with code blocks, headings, and tables exempt,
  which is what lets contract tables and long validation commands stay readable.

### Evidence

- PR #126; the weather workflow smoke coverage was updated to use the new config so the
  per-workflow doc check stayed real rather than passing vacuously.

### Links

- <https://github.com/sympoies/nils-alfredworkflow/pull/126>
- `.rumdl.toml`, `scripts/ci/markdownlint-audit.sh`

## 2026-03-28 - Third-party artifact generation is made deterministic

### Result

- Rust dependency artifacts are now generated from the union of supported macOS and Linux
  targets, and both generated inventories were regenerated from that stable input set.

### Why / context

- Generating from whatever target the current host resolves meant a Linux developer and the
  macOS release runner produced different inventories from the same lockfile, so the strict
  drift gate failed for reasons unrelated to the change under review.
- Fixing the input set (rather than relaxing the gate) keeps the artifacts usable as a
  compliance record.

### Evidence

- Commits `93a5c7a` and `b259f85`, with regression coverage added for the new artifact
  contract wording.

## 2026-03-12 - Pasted queries stop waiting on the coalesce window

### Result

- Shared search coalescing defaults to opt-in whenever an Alfred queue delay is already
  active, and Google suggestion rows gained a direct "Show Web Results" action.

### Why / context

- The direct-results action exists so a user who already knows the query does not have to

### Evidence

## 2026-03-09 - Market favorites load in parallel without reordering rows

### Result

- Favorites quote resolution is parallelized while preserving Alfred row order and the
  existing fallback behavior; icon-cache temp writes are unique per concurrent writer.

### Why / context

- Favorites fan out to several providers; serially that is the slowest row set in the
  workflow. Parallelizing it is only safe if row order stays deterministic, because Alfred
  row order is the user's mental model of the list.
- Concurrent writers sharing one temp path in the icon cache is the classic corruption
  case; per-writer temp names remove it and are covered by regression tests.

### Evidence

- PR #121, validated in-commit with `scripts/local-pre-commit.sh` and the workflow smoke
  tests.

### Links

- <https://github.com/sympoies/nils-alfredworkflow/pull/121>

## 2026-03-08 - Weather caches geocoding and gains batch multi-city forecasts

### Result

- City geocoding results are cached ahead of provider calls, weather rows carry structured
  icon metadata including night variants, and `weather-cli` supports batch multi-city daily
  fetches through repeated `--city` flags.
- Subtitles now show the forecast date and the location's timezone.

### Why / context

- Geocoding is a separate provider call from the forecast itself, so an uncached lookup
  doubled latency for every keystroke on a city name the user had already resolved.
- Batch fetching exists because the multi-city view previously issued one request per city,
  which is both slow and the fastest way to hit a provider rate limit.
- Showing the location timezone in the subtitle resolves the ambiguity of "tomorrow" when
  the user is checking a city on the other side of the date line.

### Evidence

- Commits `86e4a55`, `c79ea60`, `fa71649`, and PR #120; negative coordinates and timezone
  metadata are asserted so the cache cannot silently drop a hemisphere sign.

### Links

- <https://github.com/sympoies/nils-alfredworkflow/pull/120>

## 2026-03-07 - Workflow installs preserve user customizations

### Result

- The install path was streamlined so re-installing a workflow preserves the user's
  configuration instead of resetting it to manifest defaults, and shared smoke helpers
  (bundle ID, manifest path, wait, artifact restoration) were extracted.
- The packaging guide moved under `docs/` as a governed document.

### Why / context

- Users configure API keys, regions, and cache paths in the Alfred UI. An upgrade that
  resets those fields is indistinguishable from data loss, and it is the single most
  likely way for a routine release to break a working setup.
- The shared smoke helpers exist because each workflow's smoke test had reimplemented the
  same bundle and manifest lookups, and the copies disagreed about where a packaged
  artifact lives.

### Evidence

- PRs #117 (install preservation and smoke helpers) and #118 (packaging guide placement).

### Links

- <https://github.com/sympoies/nils-alfredworkflow/pull/117>
- `docs/PACKAGING.md`

## 2026-03-07 - Cambridge switches to smart lookup with a self-installing runtime

### Result

- Cambridge lookup now detects an exact match and returns detail rows directly, with `cds`
  kept as the explicit suggestion mode; example rows are rendered and suggestion parsing
  handles both direct-entry and spellcheck pages.
- The workflow installs its own workflow-local Playwright and Chromium runtime on the first
  live lookup.

### Why / context

- The previous flow always went through suggestions, so looking up a word the user spelled
  correctly cost an extra step and an extra page load.
- Cambridge serves structurally different pages for a direct hit and a spellcheck
  redirect; parsing only one of them made correctly spelled rare words look like failures.
- Self-installing the runtime removes the manual setup step that made this the only
  workflow a user could install and still not be able to run.

### Evidence

- PRs #113 (example rows and parser hardening) and #114 (smart lookup plus bootstrap).

### Links

- <https://github.com/sympoies/nils-alfredworkflow/pull/114>

## 2026-03-03 - CI is refactored into shared bootstrap and gate entry points

### Result

- CI gained shared bootstrap and gate entry points (`scripts/ci/ci-bootstrap.sh`,
  `scripts/ci/ci-run-gates.sh`), a workflow drift audit, a frozen shared CLI runtime
  contract, migrated CLI crates onto the shared runtime helpers, and an enforced
  shared-helper stack with an orphan-script contract.
- Docs pruning produced an ownership matrix; a docs freshness and local-reference audit
  became a lint gate. CI then ran for every pull request, not only ones targeting `main`.

### Why / context

- The GitHub workflow files had accumulated per-job setup that drifted from what the local
  gate ran, so "green locally, red in CI" was routine. One bootstrap and one gate runner
  make the local command and the CI job the same code path.
- The orphan-script contract closes the gap where a helper stops being referenced but stays
  packaged: dead shell in a shipped workflow is indistinguishable from live shell during an
  incident.
- The branch filter on `pull_request` meant stacked branches ran no CI at all until they
  retargeted `main`, which is exactly when a regression is cheapest to catch.

### Evidence

- Issue #95 delivered as PR #105, composed of #96-#104; follow-up `4e53cfc` restored the
  runtime bootstrap prerequisites (including ripgrep on Debian/Ubuntu) and the
  helper-loader policy markers.

### Links

- <https://github.com/sympoies/nils-alfredworkflow/pull/105>
- `docs/specs/ci-refactor-contract.md`, `docs/specs/cli-shared-runtime-contract.md`

## 2026-03-02 - Third-party license and notice artifacts become generated and gated

### Result

- A deterministic generator produces `THIRD_PARTY_LICENSES.md` and
  `THIRD_PARTY_NOTICES.md`; strict CI audit gates catch drift, the release flow regenerates
  and commits them during version sync, and release-time compliance gates were added.
- Troubleshooting gained a dedicated third-party license incident route.

### Why / context

- The repository publishes binaries built from a large dependency tree, so the license
  inventory is a release obligation rather than a document. Generated-plus-gated is the only
  arrangement where the obligation cannot quietly go stale between releases.
- The generator retries crates.io runtime metadata fetches because a transient registry
  failure otherwise fails a release for a reason unrelated to the release.
- MPL source metadata was added to the notices because that license requires pointing at
  the source, which a license name alone does not satisfy.

### Evidence

- Issue #85 delivered as PRs #86 (contract), #87 (generator regression coverage), #88
  (incident routes), #89 (audit gates), and #90 (release compliance gates).

## 2026-03-02 - pin-crates verifies crates.io before it pins

### Result

- The pin automation now validates that the selected version is actually published on
  crates.io before rewriting any pin, and fails fast when the version is unavailable or the
  lookup fails. It also gained auto commit and push.

### Why / context

- Pinning to a version that does not exist rewrites a dozen files and only fails later, at
  build time, in a state where the docs, manifests, and lockfile already claim the bad
  version.
- The codex-cli `cxau` smoke cache paths were isolated in the same change, because an
  external cache on the developer's machine could otherwise make the pin smoke test pass or
  fail for reasons unrelated to the pin.

### Evidence

- Commits `e4603fe` and `f65c82c`; pin-crates smoke coverage now includes the
  missing-version failure path.

## 2026-03-02 - Repository ownership moves from graysurf to sympoies

### Result

  tests were changed to resolve CLI binary paths at runtime.

### Why / context
