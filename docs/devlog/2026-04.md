# Development log - 2026-04

## 2026-04-27 - The unwrap/expect gate settles on warn-plus-summary, with the first crate denied

### Result

- The strict clippy invocation in `scripts/workflow-lint.sh` allows
  `clippy::unwrap_used` and `clippy::expect_used`, the dedicated CI step that counts them
  is non-blocking, and `randomer-cli` became the first crate to `deny` both at its crate
  root after its three production `expect()` callsites were removed.

### Why / context

- Setting the workspace lints to `warn` was the point, but the strict gate runs with
  `-D warnings`, which silently promoted them to errors and would have blocked every
  unrelated change until the whole workspace was clean.
- The CI summary step was also made `continue-on-error` and stopped piping through `tee`,
  because a `pipefail` trip on a transient cargo exit failed the validate job before the
  summary it exists to publish had even rendered.
- The intended progression is recorded in the guide: warn workspace-wide, then per-crate
  `deny` once that crate's production paths route failures through `?` and a
  `NILS_<DOMAIN>_NNN` code. `randomer-cli` establishes that pattern, keeping `expect()`
  allowed in test modules.

### Evidence

- PRs #155 (workspace gate), #157 (randomer cleanup and crate-root deny), plus commits
  `7be5a57` and `6a9e3b6` for the gate corrections.

### Links

- <https://github.com/sympoies/nils-alfredworkflow/pull/155>
- <https://github.com/sympoies/nils-alfredworkflow/pull/157>

## 2026-04-27 - codex-cli temp files are swept by an EXIT trap

### Result

- `script_filter.sh` and `action_open.sh` register every `mktemp` path in a script-level
  array and sweep it from an EXIT/INT/TERM trap, instead of relying on a trailing `rm -f`.

### Why / context

- SIGINT during a slow `codex` invocation, a `jq`/`awk` failure on an early-return path, or
  a `set -e` exit between `mktemp` and `rm` leaked capture files into `$TMPDIR` until
  reboot. Alfred cancels Script Filters constantly, so the interrupted case is the normal
  one, not the exception.
- The subshell-local trap inside `script_filter.sh` was deliberately left intact: it lives
  in its own `( ... )` context and is not replaced by the script-level trap.

### Evidence

- PR #156; seven `mktemp` callsites (five in `script_filter.sh`, two in `action_open.sh`)
  register with the array. The follow-up silences SC2317/SC2329 on the trap-only helper and
  rewrites `A && B || C` as a plain `if` to avoid SC2015.

### Links

- <https://github.com/sympoies/nils-alfredworkflow/pull/156>

## 2026-04-26 - cargo-deny gates advisories, licenses, bans, and sources

### Result

- `deny.toml` codifies the policy that `THIRD_PARTY_LICENSES.md` previously only implied,
  and a dedicated workflow runs `cargo deny check advisories bans licenses sources` on
  push, pull request, and a daily cron.

### Why / context

- Advisories are published against dependencies that have not changed, so a push-triggered
  gate alone never fires on a quiet branch. The daily cron is what makes a new advisory
  visible without a commit.
- `RUSTSEC-2025-0066` (`google-apis-common` unmaintained) is ignored explicitly: upstream
  offers no safe migration target, and pretending otherwise by removing the gate would hide
  the next advisory too. The ignore is a tracked decision, not a silence.

### Evidence

- PR #154; the allow list covers the common OSI licenses plus the CC0-1.0 used by the
  workspace crates, warns on duplicate versions, and denies unknown registries.

### Links

## 2026-04-26 - Error codes finish migrating to the `NILS_<DOMAIN>_NNN` registry

### Result

- The remaining generic dot-namespaced codes in `workflow-cli`, `market-cli`, `weather-cli`,
  and `workflow-readme-cli` moved onto registry-aligned identifiers, `memo-workflow-cli`
  gained `NILS_MEMO_001`/`002`, and the registry grew the
  `NILS_WORKFLOW_README_001..012` range and a `NILS_WORKFLOW_003` seed.
- Failures now print as `error[NILS_<code>]: <msg>` on stderr, matching the `workflow-cli`
  human path.

### Why / context

- This is a breaking change for envelope consumers: `error.code` no longer emits
  `user.invalid_input` or `runtime.provider_failed`. It was accepted because dot-codes were
  per-crate strings with no registry, so nothing outside the crate could map a code to a
  meaning or reserve a range.
- `weather-cli`'s `runtime.provider_failed` literal was collapsed onto `NILS_WEATHER_002`
  through a shared constant mirroring `market-cli`, so the two crates stop describing the
  same failure two ways.
- Five CLIs (`bangumi`, `bilibili`, `memo-workflow`, `steam`, `workflow-readme`) were also
  added to the crates.io publish order: none had `publish = false`, so `publish-crates.sh`
  had been skipping them silently.

### Evidence

- PRs #150 (generic codes), #151 (publish order), and #152 (memo codes); the publish dry run
  packages all 21 crates with no dependency-order errors.

### Links

- <https://github.com/sympoies/nils-alfredworkflow/pull/150>
- <https://github.com/sympoies/nils-alfredworkflow/pull/151>

## 2026-04-25 - The CLI output flag and envelope version are aligned with the canonical spec

### Result

- `ENVELOPE_SCHEMA_VERSION` now emits `cli-envelope@v1`. Thirteen CLIs migrated from
  `--mode service-json|alfred` (or `-j`/`-p`) to `--output <human|json|alfred-json|plain>`,
  and four newer CLIs dropped the deprecated `--json` boolean alias so clap enforces value
  validation.
- Twelve script-filter CLIs moved from `<crate>.user` / `<crate>.runtime` strings to
  `NILS_<DOMAIN>_001` / `_002`.

### Why / context

- This is deliberately a breaking change for external callers, taken while the crates were
  young: two spellings of the same flag and two shapes of the same envelope is a contract
  the repository would have had to honor indefinitely.
- `plain` is retained only as a google-cli extension and is marked as such in the spec, so
  it cannot drift into a general mode.
- Eighteen workflow shell callers, two smoke fixtures, and the weather troubleshooting doc
  were updated in the same change, since a partially migrated caller is invisible until a
  user runs that row.

### Evidence

- PRs #148 (output flag and envelope) and #149 (error codes); the registry gained reserved
  ranges and seed rows for bangumi, bilibili, and steam, with `_001` standardized as
  invalid user input and `_002` as the runtime/upstream failure.

### Links

- <https://github.com/sympoies/nils-alfredworkflow/pull/148>
- <https://github.com/sympoies/nils-alfredworkflow/pull/149>

## 2026-04-25 - Test targets are consolidated and the dev profile is trimmed

### Result

- Each crate's `tests/*.rs` files were collapsed into one `tests/integration.rs` plus
  `integration/` submodules, `[profile.dev]` gained `debug = "line-tables-only"` and
  `split-debuginfo = "unpacked"`, and the `sccache` setup was dropped from the Rust
  bootstrap.

### Why / context

- Cargo links one binary per integration test file. With 21 crates each carrying several
  test files, link time dominated the local loop; one target per crate removes most of it
  while keeping the tests separated by module.
- `sccache` only activated when it happened to be on `PATH` and produced no measurable
  win, so the bootstrap kept a dependency that did nothing.
- `cli-standards-audit` was retargeted at `tests/integration/cli_contract.rs` with a legacy
  fallback so the audit did not have to land atomically with every crate's move.

### Evidence

- PRs #137 (test consolidation and dev profile) and #138 (sccache removal).

### Links

- <https://github.com/sympoies/nils-alfredworkflow/pull/137>

## 2026-04-25 - Advisory-driven dependency bumps: rand and rustls-webpki

### Result

- Transitive `rand` 0.8.5 was pinned to 0.8.6 for RUSTSEC-2026-0097, `rustls-webpki`
  advanced to 0.103.13 for two name-constraint advisories, and `rand` 0.9.2 moved to 0.9.3
  for the custom-logger unsoundness advisory. Generated license and notice artifacts were
  regenerated with each bump.

### Why / context

- `rand` 0.8.5 arrives only as a feature-gated optional dependency of `rust_decimal` and is
  not in any build, but the advisory gate reads the lockfile, not the feature graph;
  pinning is cheaper than arguing with the gate on every run.
- Every one of these bumps rotates the `Cargo.lock` SHA256 recorded in the generated
  artifacts, which is why an artifact refresh accompanies each bump and why strict audit
  failures on `main` trace back to a missed refresh rather than a real license change.

### Evidence

- PRs #136 and #139, plus commits `60ffba8` and `05892f4`.

### Links

- <https://github.com/sympoies/nils-alfredworkflow/pull/139>

## 2026-04-22 - open-project opens any forge host, not just github.com

### Result

- The web-open action parses the host from the git origin and emits
  `https://<host>/<path>` for any host. `github.com` keeps strict owner/repo parsing, while
  other hosts accept two or more path segments so GitLab subgroups resolve.

### Why / context

- The original implementation hardcoded github.com, so a GitLab, Gitea, Bitbucket, or
  self-hosted repository produced no web row at all. Requiring configuration for that would
  have meant a UI field per host.
- GitHub keeps the strict two-segment rule because its URL shape is fixed and a loose parse
  there would happily produce broken links from unusual remotes.

### Evidence

- PR #135; resolution is zero-config, with no environment variables or Alfred UI fields.

### Links

- <https://github.com/sympoies/nils-alfredworkflow/pull/135>

## 2026-04-17 - Cambridge self-heals its runtime across Playwright binary bumps

### Result

- The Cambridge runtime bootstrap detects and repairs itself when a Playwright version bump
  invalidates the installed browser binaries.
- `.agents/scripts/release.sh` and `.agents/scripts/pre-pr.sh` were added as thin
  dispatchers over the release skill and the local pre-commit gate.

### Why / context

- A Playwright package bump changes the expected browser revision, so a previously working
  install starts failing with a missing-executable error that looks like a broken workflow
  rather than a stale cache. Self-healing turns that into a one-time slow lookup.
- The `.agents` dispatchers exist so `/release` and `/pre-pr` resolve to the same scripts
  the repository already owns, instead of each agent surface re-deriving the command.

### Evidence

- PR #131 and commit `2e92aae`.
