## 2026-02-28 - google-cli replaces the `gog` wrapper with a native Google API client

**Result**

- `google-cli` moved from a thin wrapper around an external `gog` binary to a native Rust
  client over the Google APIs, delivered as five sprints: contracts and module skeleton,
  auth core, Gmail commands, Drive read/upload and download lanes, then runtime and docs
  migration.
- Auth storage, OAuth flow, and account resolution became crate-owned, so the workflow no
  longer depends on a third-party runtime being installed.

**Why / context**

- The wrapper made the Alfred surface only as reliable as an unmanaged external binary and
  gave the repository no way to pin, audit, or test the Google call path.
- The sprint split was deliberate: each sprint landed its own contract tests so the
  `no-gog` behavior could be asserted before the next lane removed more of the runtime
  dependency. Drive was split into two lanes (read/upload, download) that merged
  independently, which is why the fallback contract tests were realigned twice.
- `google-drive3` and `google-gmail1` were normalized onto 7.0.0 releases so the two API
  surfaces share one generated-client generation.

**Evidence**

- Sprint PRs #75 (scaffold), #76 (auth core), #77 (Gmail), #78 and #79 (Drive lanes), #80
  (runtime and docs migration), and #81 (native API execution and docs consolidation).
- Each sprint carried integration tests asserting the native path runs with no `gog`
  present; `crates/google-cli` contract tests isolate `GOOGLE_CLI_CONFIG_DIR` so the
  empty-account case asserts the auth-resolution error code rather than a host-dependent
  failure.

## 2026-02-23 - Script Filter runtime survives a missing or failing `jq`

**Result**

- Fallback Script Filter JSON now escapes control characters, and malformed JSON is guarded
  when `jq` is unavailable on the host.

**Why / context**

- Alfred renders nothing and reports no useful error when a Script Filter emits invalid
  JSON, so an unescaped control character in an error message turned a recoverable backend
  failure into a silent dead end.
- `jq` is a host binary the workflow cannot assume; the guard keeps the error path
  self-contained rather than requiring a dependency to report a dependency problem.

**Evidence**

## 2026-02-22 - macOS Gatekeeper quarantine handling is centralized, then automated

**Result**

- Per-workflow quarantine workarounds were replaced by one centralized fix, published as a
  standalone release asset, and then made automatic: workflows clear their own quarantine
  attribute on startup.

**Why / context**

- Every bundled Rust binary downloaded inside a workflow `.alfredworkflow` inherits
  `com.apple.quarantine`, and Gatekeeper then blocks execution with an error Alfred cannot
  explain. Early workflows each carried a local `xattr` call, so a new workflow silently
  shipped broken until someone noticed.
- Publishing the standalone script as a release asset covers the case where a user's
  install is already quarantined and the workflow cannot run far enough to fix itself.

**Evidence**

- PRs #54 (centralized fix), #55 (standalone release asset), and #56 (startup auto-clear).
- Release 1.1.6 published the standalone quarantine asset, and the README documents the
  manual recovery path.

**Links**

## 2026-02-14 - Script Filter throttling and the short-query gate become policy

**Result**

- A shared Script Filter query policy set a 1-second queue delay with the immediate initial
  run disabled, and gated queries shorter than two characters, across the search and codex
  workflows.
- The policy is machine-readable and synchronized into workflow plists by
  `scripts/workflow-sync-script-filter-policy.sh --check`.
- A shared async coalesce cache helper landed alongside it.

**Why / context**

- Alfred invokes a Script Filter on every keystroke. Without a queue delay, typing a
  six-character query fired six backend calls, and for `codex-cli` those calls were
  `auth current` and `diag` invocations that are expensive and rate-limited.
- One- and two-character queries almost never produce useful results from these backends,
  so gating them removes the most wasteful calls without changing what users can search.
- Encoding the policy as data plus a `--check` gate prevents the usual drift where one
  workflow's plist quietly loses its delay during an unrelated edit.

**Evidence**

- PRs #30 and #31 (shared throttle), commit `5a91e8f` (Cambridge debounce alignment), and
  the async coalesce helper in `8d24f59`.

**Links**

- <https://github.com/sympoies/nils-alfredworkflow/pull/31>
- `docs/specs/script-filter-input-policy.md`

## 2026-02-11 - codex-cli workflow adds auth management and cached diagnostics

**Result**

- The `codex-cli` workflow shipped with `cx`/`cxa`/`cxd`/`cxda`/`cxs` flows for login, auth
  save, and diagnostics, backed by a diag result cache with TTL auto-refresh, per-mode
  cache paths, and an `auth.json` fallback when no saved secrets exist.
- Later in the week it gained `cxau` (auth use), `cxr` (auth remove) with confirmation
  handling, usage labels showing percent plus remaining time, and account rows that survive
  partial diag failures.

**Why / context**

- `codex diag` is slow and rate-limited, so rendering it inline on every keystroke was not
  viable; the cache is what makes the rows usable at Alfred speed.
- Caching per mode (rather than a single "last" file) was needed because a cached `all-json`
  result and a default-mode result are not interchangeable, and reusing one for the other
  displayed rows for accounts the user had not asked about.
- Partial failures are the normal case when one account's token has expired; preferring
  stdout JSON over stderr noise and parsing cached rows on a non-zero exit keeps the other
  accounts visible instead of blanking the list.
- `cxr` requires the secret file to exist before offering a remove row, so a confirmation
  prompt never appears for something that cannot be removed.

**Evidence**

- PRs #18, #19, #23, #34, #35, and #36; smoke tests cover alias routing, `all-json`
  behavior, cache refresh, partial account expiry, and the missing-file remove path.
