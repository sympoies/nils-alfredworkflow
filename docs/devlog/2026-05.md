# Development log - 2026-05

## 2026-05-30 - agent-docs v0.30 surface adoption adds a finish-line validation gate

**Result**

- Retired `resolve --context` references were replaced by `preflight --intent` and `audit`,
  and `AGENT_DOCS.toml` declares a `[[validation]]` contract so the local pre-commit gate
  must run before a `project-dev` task is declared done. `.cache/` is gitignored for the
  gate marker.
- Six ad-hoc plan and discussion files predating the dated plan-folder convention were
  removed.

**Why / context**

- Declaring the finish-line command as data means the enforcement lives with the repository
  rather than in each agent's habits; the marker file is what makes "validated" observable
  instead of asserted.
- The removed plan files had no provider-ref-backed folder, so there was nothing to migrate
  into the archive convention and keeping them would have implied they were still tracked
  work.

**Evidence**

- PR #172 and commit `e7dc157`; the local gate is `bash scripts/local-pre-commit.sh`.

**Links**

- <https://github.com/sympoies/nils-alfredworkflow/pull/172>
- `AGENT_DOCS.toml`

## 2026-05-29 - Customizable hotkey triggers land across the workflow set

**Result**

- Workflow templates gained customizable (unassigned by default) hotkey triggers, backed by
  `scripts/workflow-hotkey-policy.sh` as a lint gate, with `codex-cli` hotkey connections
  and smoke assertions updated for the new plist layout.

**Why / context**

- Alfred hotkeys are per-user bindings; shipping them pre-assigned would collide with
  whatever the user already uses, so every trigger ships unassigned and the workflow only
  guarantees the wiring exists.
- The policy gate exists because hotkey objects are plist nodes with connections, and an
  edit elsewhere in the plist silently drops them; the smoke assertions count objects and
  connections precisely for that reason.

**Evidence**

- Commits `eb11126`, `e33fb8d`, and `0575a51`.

**Links**

- `scripts/workflow-hotkey-policy.sh`

## 2026-05-29 - Steam Search adds specials, discount ranking, and cover art

**Result**

- Discounted results sort first with strike-through prices, an empty query routes to
  Steam's featured categories endpoint with its own ranking, and both specials and search
  rows carry cached cover art (`STEAM_SHOW_COVERS`, `STEAM_COVER_CACHE_DIR`).

**Why / context**

- An empty query previously returned nothing; routing it to featured specials turns the
  workflow's idle state into the answer to "what is on sale", which is the main reason to
  open a store search.
- Cover art is cached on disk rather than fetched per render because Alfred re-renders rows
  on every keystroke and remote icon fetches would make the list stutter.

**Evidence**

- Commits `a513e36`, `5aa0802`, `06ef9b7`, `93129de`, and `6829744`, released in 1.3.1.

## 2026-05-29 - Packaged plist smoke assertions are shared, and artifact drift is gated first

**Result**

- Reusable smoke helpers now cover the common packaged Script Filter and action wiring
  checks, with representative search workflows migrated onto them and the helper documented
  for new workflow scaffolds.
- A changed-input third-party artifact gate runs before the rest of the local pre-commit
  checks.

**Why / context**

- Each workflow's smoke test had reimplemented the same packaged-plist assertions, so a new
  workflow's coverage was only as good as whichever neighbour was copied.
- Running the artifact drift gate first matters because artifact drift makes every later
  strict audit fail; discovering it after a full lint and test cycle wastes the whole run.
  The gate planner covers lockfile, runtime pin, crate manifest, generated artifact, and
  unrelated-doc cases so it stays quiet when nothing relevant changed.
- A stale `--mode` grep in the google-search smoke stub was also corrected to `--output`,
  which had been quietly making the coalesce-avoidance assertion meaningless since the flag
  migration.

**Evidence**

- PR #170 and commits `67e883f` and `6759353`.

**Links**

- <https://github.com/sympoies/nils-alfredworkflow/pull/170>

## 2026-05-24 - Forge Inbox ships as a provider-aware review queue

**Result**

- `forge-inbox` renders `forge-cli inbox` JSON in provider and item modes with open and copy
  actions, fixed-provider shortcuts (`fih`, `fil`), provider-specific row icons, unassigned
  hotkeys, and env passthrough for GitLab readiness, timeout, strict, and cache flags
  exposed as Alfred configuration fields.

**Why / context**

- A self-hosted GitLab is often only reachable over VPN, so the readiness probe and timeout
  had to be user-tunable: a fixed timeout either stalls the Script Filter off-VPN or gives
  up too early on a slow tunnel.
- The GitLab missing-host prompt is hidden unless config warnings are enabled, because a
  GitHub-only user should not see a permanent warning row for a provider they never
  configured.
- `open-project` was updated in the same period to detect GitLab origins and use the GitLab
  icon, so the two workflows identify the same repository the same way.

**Evidence**

- PRs #165 (workflow), #166 (provider shortcuts and icons), plus commits `2bc039d`,
  `9404269`, `ba60477`, `b4a781b`, and `e1b3c44`; smoke coverage pins version-aware
  packaged-artifact selection and the hidden-prompt behavior.

**Links**

- <https://github.com/sympoies/nils-alfredworkflow/pull/165>
- <https://github.com/sympoies/nils-alfredworkflow/pull/166>

## 2026-05-22 - Google Service smoke tests stop touching the desktop

**Result**

- Reusable `osascript` and `xdg-open` stubs were added, and the Google Service action checks
  route through them.

**Why / context**

- The smoke tests were invoking real UI commands, so running the suite opened browser tabs
  and touched the clipboard on the developer's machine, and the assertions depended on
  those side effects succeeding. Stubbing makes the test assert what the workflow *asked*
  the desktop to do, which is the part the workflow actually owns.

**Evidence**

- Issue #162 delivered as PR #163.

**Links**

- <https://github.com/sympoies/nils-alfredworkflow/pull/163>

## 2026-05-17 - google-cli adapts to keyring 4

**Result**

- The `keyring` major bump from 3.6.3 to 4.0.1 was absorbed by adapting the google-cli
  credential storage path, and the `open` 5.3.5 bump was merged with refreshed notices.

**Why / context**

- `keyring` owns where OAuth tokens live on the user's machine; a major bump that changes
  the storage API is the one dependency update that can silently orphan existing
  credentials, so it was taken as its own adaptation rather than a lockfile bump.

**Evidence**

- PRs #159 and #160, plus commit `f881ca5`.

**Links**

- <https://github.com/sympoies/nils-alfredworkflow/pull/160>

## 2026-05-09 - Local Python helpers move to uv-managed isolation

**Result**

- The repository's helper virtualenv is created with `uv`, `.envrc` bootstraps it through
  direnv when missing, and the guide documents how direnv-managed and one-off isolated runs
  differ.

**Why / context**

- Several audit scripts embed Python. Without a declared environment they ran against
  whatever interpreter the host happened to expose, which is how an audit passes locally and
  fails in CI for reasons that have nothing to do with the change.

**Evidence**

- Commits `4e46547`, `4820c33`, and `bf1ca4c`.

**Links**

- `.envrc`, `docs/MAINTENANCE.md`
